# 這題的筆記

> 目標是確定有沒有用對 Cpp 工具版本號、以及學會ASan記憶體偵錯工具的使用

## 1. Stage 0 問題

- Q1 202002 這個數字怎麼編碼出來的?為什麼不是 20 / 2020?（提示:__cplusplus 在 C++17 時是多少?）

1. __cplusplus 印出的是Cpp的版本號
    就這題: __cplusplus = 202002 代表年分月份
    ┌───────┬─────────────┐
    │ 標準  │ __cplusplus │
    ├───────┼─────────────┤
    │ C++11 │ 201103L     │
    ├───────┼─────────────┤
    │ C++14 │ 201402L     │
    ├───────┼─────────────┤
    │ C++17 │ 201703L     │
    ├───────┼─────────────┤
    │ C++20 │ 202002L     │
    ├───────┼─────────────┤
    │ C++23 │ 202302L     │
    └───────┴─────────────┘
    關於上述表格的數字，屬於單調遞增，所以可以在code中做以下這種版本篩檢的操作:
    ```cpp
    if __cplusplus >= 202002L
        ...
    ```


- Q2 假設哪天 ASan 沒報錯、程式安靜跑完印出 99,p[3] = 99 就是安全的嗎?為什麼?
    ```
    不安全,因為那是 undefined behavior。UB 的定義是「標準不保證任何事」,不是「一定會爆」。程式沒崩只代表這次的 UB 長得像正常行為,不代表它安全。
    ```

    那一行確實可以改，但是可能會改到其他人的資訊，在未來會爆炸，ASan 可以指出這件事情
    ```
    ① 錯誤標頭
    ERROR: AddressSanitizer: heap-buffer-overflow on address 0x50200000001c
    WRITE of size 4 at 0x50200000001c thread T0
    ```

- Q3 -Wall -Wextra 為什麼沒抓到第 16 行?編譯器在第 16 行看到的 p 是什麼型別?那個「3」在型別裡嗎?

    ```
    p 型別是 int*。int* 這個型別裡沒有長度資訊。

    對照組:
    int a[3];
    a[3] = 99;      // 型別是 int[3],長度在型別裡 → -Warray-bounds 會警告
    int* p = new int[3];
    p[3] = 99;      // 型別是 int*,長度已丟失 → 編譯器沉默

    ```
## 2. 基本的流程
寫code -> 編譯 -> (編譯報錯與否) -> 執行 ./main -> (ASan執行報錯與否)
- 編譯的 flag
    > 舉例:
    > g++ -std=c++20 -Wall -Wextra -g -fsanitize=address main.cpp -o main
    ```
    ┌────────────────────┬─────────────────────────────────────────────────┐
    │        旗標        │                      作用                       │
    ├────────────────────┼─────────────────────────────────────────────────┤
    │ g++                │ GNU C++                                         │
    │                    │ 編譯器驅動程式。它自己不編譯,是指揮下面四支工具 │
    ├────────────────────┼─────────────────────────────────────────────────┤
    │ -std=c++20         │ 用哪版標準。決定 __cplusplus 的值、能不能用     │
    │                    │ std::span                                       │
    ├────────────────────┼─────────────────────────────────────────────────┤
    │ -Wall              │ 開常用警告。名字騙人 —— 不是                    │
    │                    │ all,只是「大家公認該開的那批」                  │
    ├────────────────────┼─────────────────────────────────────────────────┤
    │ -Wextra            │ 再補一批 -Wall 沒含的。這兩個一起才算基本盤     │
    ├────────────────────┼─────────────────────────────────────────────────┤
    │ -g                 │ 把 debug info(.debug_line 等)寫進執行檔 → ASan  │
    │                    │ / gdb 才能給行號                                │
    ├────────────────────┼─────────────────────────────────────────────────┤
    │ -fsanitize=address │ 開 ASan:插 redzone、改寫每次記憶體存取、連結    │
    │                    │ libasan                                         │
    ├────────────────────┼─────────────────────────────────────────────────┤
    │ main.cpp           │ 輸入                                            │
    ├────────────────────┼─────────────────────────────────────────────────┤
    │ -o main            │ 輸出檔名。不給的話預設叫 a.out                  │
    └────────────────────┴─────────────────────────────────────────────────┘
    ```

- 執行的工具 ASan (Address Sanitizer):內建的記憶體偵錯工具
在每次記憶體存取前後 做邊界檢查。跑起來比正常執行慢(通常 2x 左右),但能抓到這幾類 C++ 最頭痛的 bug:

| 錯誤類型 | 範例 |
|---|---|
| **Heap buffer overflow** | 你 Stage 2 那個故意寫錯陣列大小的練習 |
| **Use-after-free** | `delete` 之後還去讀寫那塊記憶體 |
| **Double free** | 同一塊記憶體 `delete` 兩次 |
| **Stack buffer overflow** | 區域陣列越界寫入 |
| **Memory leak**(需搭配 LeakSanitizer,通常內建一起開) | `new` 了忘記 `delete` |

由於跑起來會比正常慢，因此可以衡量需求考量開啟偵錯。
